# Netkit Lab Generator
A tool to configure a Kathará or a Netkit lab and generate all the files you need and the topology graph. 

It works as stand-alone HTML file or using Electron for some advanced capabilities (like the ability to directly run a lab from inside the UI).

![Screenshot (graph)](https://raw.githubusercontent.com/Kidel/Netkit-Lab-Generator/master/images/screencapture-201801143.png)

Simply fill the form and download the bash script or the .zip file with the whole lab. 
It is also possible to export and import the form configuration for future changes.

Now supports network topology preview (requires a modern browser or the Electrum release).

### FAQ

* **Q**: How can I make a machine that is both a web server and a name server?
* **A**: Two machines with the same name are considered as the same machine. For any shared file, the configuration lines of the second machine are added right after the ones of the first machine. For any file that is not shared there is no conflict.

### Docker (browser-only deployment)

The app can be served as a **static web application** using an unprivileged
Nginx Alpine container. No Node.js runtime, Electron, Kathará daemon or Docker
socket is required inside the container.

With Docker Compose:

```sh
docker compose up -d --build
```

Then open **http://localhost:8080** from the Docker host.

With Docker alone:

```sh
docker build -t netkit-lab-generator:local .
docker run -d --name netkit-lab-generator -p 8080:8080 \
  --restart unless-stopped netkit-lab-generator:local
```

Check that the service responds:

```sh
curl -fI http://localhost:8080/
```

Stop a Compose deployment using `docker compose down`.

**Important limitations:**

- This image serves only the browser UI. The Electron-only **Run on Host**
  feature cannot start Kathará containers from this web server. Generated
  laboratory scripts and ZIP files are still downloadable to run separately
  on a machine with Kathará installed.
- **My saved laboratories** uses IndexedDB in each visitor's browser; there
  is no server-side storage volume. Export a `.config` backup if the data
  must survive a browser-profile reset or be moved between computers.
- Chrome's native file save picker requires a secure context such as
  `https://` or `http://localhost`. When browsing over ordinary HTTP from
  another computer, the app falls back to the browser's normal download flow.
- Exposing the container on a public network should be done behind a
  HTTPS reverse proxy with appropriate access controls.

#### Download official Kathará examples with curl

The Docker image bundles **three original ZIP archives** from the
[Kathara-Labs repository](https://github.com/KatharaFramework/Kathara-Labs)
at a pinned upstream revision. They are available at the HTTP endpoint
`/labs/`, without any additional backend or storage service.

```sh
# The full name generated by the Basic IPv4 lab description:
curl -fL http://localhost:8080/labs/basic_ipv4_configurations_ping_traceroute_and_arp.zip \
  -o basic-ipv4.zip

# Short aliases:
curl -fL http://localhost:8080/labs/two-computers.zip -o two-computers.zip
curl -fL http://localhost:8080/labs/basic-ipv4.zip -o basic-ipv4.zip
curl -fL http://localhost:8080/labs/static-routing.zip -o static-routing.zip

# Validate the downloaded archive:
unzip -t basic-ipv4.zip
```

To rebuild after updating the source:

```sh
docker compose up -d --build
```

The image build requires network access to `raw.githubusercontent.com`
to download the pinned archive files, and fails if an archive is missing
or invalid.

**These are native Kathará ZIPs from the upstream repository**, not ZIPs
generated from editable configurations in the browser. Editing a lab in
the generator does not modify the downloaded native archive. The **Download Lab → curl** preview automatically uses the current page's
HTTP(S) origin (including its port) instead of a static `YOUR_SERVER` placeholder.
However, custom labs still need an HTTP upload/publication service before they
can be retrieved with `curl`.

### Prebuilt Docker image from GHCR (no local build)

After the GitHub Actions workflow has successfully published the first image,
deploy directly from GitHub Container Registry:

```sh
docker pull ghcr.io/jadjay/netkit-lab-generator:latest
docker compose -f compose.ghcr.yaml up -d
curl -fI http://localhost:8080/
```

The image is served at **http://localhost:8080**.

To update an existing deployment to the latest published image:

```sh
docker compose -f compose.ghcr.yaml pull
docker compose -f compose.ghcr.yaml up -d
```

Stop it with `docker compose -f compose.ghcr.yaml down`.

**Publishing rules:**

- Pull requests run the Node test suite and build the Docker image but **never push it**.
- Pushes to `master` publish `latest` plus a short commit-SHA tag.
- Git tags such as `v1.6.0` publish `1.6.0` and `1.6` plus the short SHA.
- The workflow uses the repository-scoped `GITHUB_TOKEN` with
  `packages: write` for publication. No personal access token is needed.

**First publication / permissions:** GitHub Container Registry packages may
initially be private. If you want anonymous `docker pull`, open your GitHub
profile's **Packages** tab, select `netkit-lab-generator`, and change
**Package settings → Change visibility** to **Public**. Until then, users need
a suitably authorized `docker login ghcr.io`. If the package name already
exists but is not associated with this repository, the workflow token may
not have publishing access; connect the package to the repository under
package settings.

The prebuilt image includes the same three official Kathará ZIPs. The
application's personal laboratory library remains client-side IndexedDB and
is not stored in Docker volumes.
